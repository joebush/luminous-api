# Luminous API Documentation — Claude Notes

## Stack
- **Platform**: [Mintlify](https://mintlify.com)
- **Format**: OpenAPI 3.0, split into per-endpoint YAML files
- **Config**: `mint.json`

## After ANY changes, always run both:
```bash
npm run build       # Bundles YAML files → api-reference/build.yaml
npm run build-mint  # Generates MDX files → mdx-api-reference/, then injects the llms.txt directive into every .mdx
```

`build-mint` chains `scripts/inject-llms-directive.mjs`, which adds a screen-reader-only blockquote linking to `/llms.txt` to every `.mdx` page so AI agents/crawlers find the index in HTML. Idempotent (sentinel: `{/* llms-directive */}`). The `.llms-directive` CSS class lives in `style.css` (Mintlify auto-loads any `.css` file in the repo).

## File Structure
```
luminous-api/
├── mint.json                        # Mintlify config, points to build.yaml
├── api-reference/
│   ├── main.yaml                    # Root OpenAPI spec — $refs all endpoint files
│   ├── build.yaml                   # Compiled output (what Mintlify reads) — do not edit manually
│   ├── <resource>.yaml              # List/create operations (e.g. sales-orders.yaml)
│   ├── <resource-singular>.yaml     # Single-record operations (e.g. sales-order.yaml)
│   └── components/                  # Reusable schemas ($ref'd from endpoint files)
└── mdx-api-reference/               # Auto-generated by build-mint — do not edit manually
```

## Adding a New Endpoint
1. Create `api-reference/<endpoint>.yaml` with the OpenAPI operation (get/post/etc.)
2. Add the path to `api-reference/main.yaml` under `paths:` with a `$ref`
   - Place static paths (e.g. `/sales-orders/export`) **before** parameterized ones (e.g. `/sales-orders/{id}`)
3. Add any new response/request schemas under `api-reference/components/`
4. Run `npm run build && npm run build-mint`

## Validating the Spec
```bash
npx swagger-cli validate ./api-reference/build.yaml
```
